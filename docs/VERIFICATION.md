# Verification Surface

`hl7v2-rs` exposes the same verification surface expected across adopted
EffortlessMetrics Rust repositories: small public badge endpoints for
repo-scoped truth, plus diff-scoped PR evidence artifacts for review and
routing.

## Public badges

The public badge endpoints live under `badges/` and are generated by:

```bash
cargo run -p xtask -- badges
cargo run -p xtask -- badges --check
```

The badge boundary is deliberately narrow:

- `badges/ripr.json` is repo-scoped static mutation-exposure signal from RIPR.
- `badges/ripr-plus.json` is repo-scoped `ripr+`; it fails closed as `error`
  until this repo produces the required test-efficiency input.
- Badges are not coverage, runtime mutation proof, release readiness, or a
  correctness claim.
- Badges must not be generated from PR-diff artifacts.

`cargo run -p xtask -- badges --check` also writes comparison output under
`target/xtask/badges/` so CI can upload the generated view without mutating the
committed endpoints.

## Badge Drift

If `cargo run -p xtask -- badges --check` reports that `badges/ripr.json` or
`badges/ripr-plus.json` is stale, treat that as repository evidence-artifact
drift. It means the checked-in badge endpoint no longer matches the generated
repo-scoped view.

The repair is deliberately mechanical:

```bash
cargo run -p xtask -- badges
cargo run -p xtask -- badges --check
```

Commit the changed file under `badges/` only when the generated diff matches
the PR's intended verification-surface change. Do not use badge drift as a
shortcut for product behavior proof, and do not treat a badge refresh as runtime
mutation, coverage, release readiness, TestPyPI, PyPI, or npm evidence.

## PR evidence

The PR evidence cockpit is diff-scoped and generated under `target/`:

```bash
cargo run -p xtask -- ripr-pr --base origin/main --head HEAD
cargo run -p xtask -- ripr-review-comments --base origin/main --head HEAD
cargo run -p xtask -- ripr-pr-summary
cargo run -p xtask -- ripr-annotations
cargo run -p xtask -- impacted-evidence
```

The canonical artifacts are:

```text
target/ripr/pr/repo-exposure.json
target/ripr/pr/repo-exposure.md
target/ripr/pr/summary.md
target/ripr/review/comments.json
target/ripr/review/comments.md
target/ripr/review/annotations.txt
target/xtask/badges/ripr.json
target/xtask/badges/ripr-plus.json
target/xtask/impacted-evidence/latest.json
target/xtask/impacted-evidence/latest.md
```

Review guidance is advisory. Only `comments[]` entries may become warning
annotations. `summary_only[]` entries remain in the Markdown/JSON artifacts and
must not become inline comments.

## Mutation routing

`cargo run -p xtask -- impacted-evidence` routes expensive verification; it
does not execute mutation. The routing policy is:

```text
mutation label            -> targeted mutation
mutation/targeted label   -> targeted mutation
release-risk label        -> targeted mutation
ripr severe gap           -> targeted mutation
mutation/full-owner label -> full-owner mutation
otherwise                 -> fast PR evidence only
```

Runtime mutation remains a separate, routed lane. RIPR evidence tells reviewers
and agents when mutation is worth paying for.
