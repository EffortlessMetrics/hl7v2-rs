# v1.5.0 Rust 1.95 Quality Ratchet

Status: published. This document describes the v1.5.0 Rust release scope. The
publish, registry-resolution, tag, GitHub release, and public install-back
receipt is
[`docs/audits/publish-v1.5.0-2026-05-15.md`](../audits/publish-v1.5.0-2026-05-15.md).

## Release Graph

The primary Rust crates.io product graph remains:

- `hl7v2`
- `hl7v2-server`
- `hl7v2-cli`

The `hl7v2-python` Rust crate is a binding backend for the public Python
`hl7v2` package. Current metadata makes it publishable as binding
infrastructure, and the selected v1.5.0 crates.io graph includes it as a
binding backend crate:

1. `hl7v2`
2. `hl7v2-python`
3. `hl7v2-server`
4. `hl7v2-cli`

This does not make `hl7v2-python` the recommended Rust API. Rust users should
depend on `hl7v2`; Python users should install the public `hl7v2` package after
the Python release lane is proven.
TestPyPI and PyPI success require separate upload and install-back receipts.

## Highlights

- Raises the workspace MSRV to Rust 1.95 and pins `rust-toolchain.toml` to
  Rust 1.95.0 with `rustfmt` and `clippy`.
- Prepares the primary Rust product graph as version `1.5.0`.
- Includes `hl7v2-python` in the selected v1.5.0 crates.io graph as a governed
  binding backend crate for the public Python `hl7v2` package.
- Tightens compiler, Clippy, no-panic, and file-policy rails without adding
  broad default CI weight.
- Keeps retained Clippy suppressions in a dedicated exceptions ledger separate
  from temporary lint cleanup debt.
- Uses exact counted no-panic identity with a no-new-debt baseline.
- Splits file existence policy from generated, executable, dependency,
  workflow, process, and network behavior ledgers.
- Adds advisory `ripr` static mutation-exposure analysis as a PR-time signal.
- Routes runtime mutation by risk, labels, nightly, manual dispatch, or release
  readiness instead of making full mutation an ordinary PR tax.
- Applies Rust 1.95 API cleanup where it reduces parser, evidence, or tooling
  complexity.
- Expands gRPC evidence parity through inline corpus summary, fingerprint, and
  diff plus configured-root evidence bundle creation, replay, and quarantine
  output surfaces.
- Adds a non-publishing release-readiness workflow for v1.5.0 proof.

## Boundaries

- This release is published to crates.io for `hl7v2`, `hl7v2-python`,
  `hl7v2-server`, and `hl7v2-cli`.
- This release does not publish to TestPyPI or PyPI.
- Binding backend crates are not promoted as the recommended Rust API.
- `ripr` remains advisory and is not branch-protection blocking.
- Runtime mutation remains the slower backstop and is not replaced by `ripr`.
- Production PyPI remains a separate explicit release decision after
  same-commit TestPyPI proof.
